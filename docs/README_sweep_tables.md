# 逐 tier 延迟表与逐 run 功率表

每个模型六张表，每张表九列（九个档）。**全部数值直接来自
`output/analysis/sweep_rungs.csv` 与 `sweep_tiers.csv`**，本页不做二次计算；
重新生成：

```bash
bash output/analysis/extract_sweep.sh
python3 output/analysis/make_tier_tables.py > docs/README_sweep_tables.md
```

## 为什么 latency 是逐 tier、power 不是

**报告里没有逐 tier 的能量。** `energy_breakdown_nj` 只有三种拆分：
`by_class`（DIE/GPU/LINK/PIM/TLB）、`by_event`（按事件名）、`by_layer`
（按 transformer 层 0–39）。`batches` 有 `tier` 字段但没有能量字段，而事件流
被 `--workload-report-events none` 关掉了，无法反推。

把能量归到 tier 需要引擎在记账时打 tier 标签，那要重跑整个 sweep。所以：
**latency 逐 tier（数据支持），power 逐 run（数据只到这里）**。

## 口径

| 量 | 定义 |
|---|---|
| `prefill_s` | 该 tier **最后一个** request 的 `prefill_end_s` − tier 起点 |
| `decode_s` | tier 终点 − 同一时刻 |
| `makespan_s` | tier 终点 − 起点 = **prefill_s + decode_s**（严格相加）|
| prefill 功率 | prefill 能量 ÷ 全 run 各 tier 的 prefill_s 之和 |
| decode 功率 | decode 能量 ÷ 各 tier 的 decode_s 之和 |
| 整体功率 | 总能量 ÷ makespan |

prefill / decode 能量取自 `by_event`：报告把每个 decode 操作命名为其 prefill
对应项的 `decode_` 前缀版（`decode_qkv`/`qkv`、`decode_ctx_pim_to_gpu`/
`ctx_pim_to_gpu` …），所以这个二分是写入端的命名约定，不是这里的猜测。

`—` 表示该档缺失（见 `sweep_completeness.csv`）。
