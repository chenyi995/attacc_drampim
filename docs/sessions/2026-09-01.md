
## 编辑正在被执行的脚本 = NFS Stale file handle

2026-09-01 12:25 我给 `experiments/run_dag_ladder.sh` 加了 `RUNGS` 环境变量支持。
当时的判断是"默认行为逐字不变,所以对正在跑的任务安全"。**那个判断的机制是错的。**

14:38 `LLAMA-33B/private_k8` 以 `rc=2` 结束:

```
run_dag_ladder.sh: error reading input file: Stale file handle
```

风险不在语义,在于 **bash 是按字节偏移增量读取脚本的**。脚本在 NFS 上被重写后,
它持有的旧 inode handle 失效,于是它在读到文件尾部时炸掉 —— 与新内容是否等价
毫无关系。

**后果(已核实)**:只有这一个任务受影响,九档 JSON 全部写出且可正常解析,
炸的是最后一步 `collect_dag_ladder.py`,即 `dag_ladder.csv` 没生成。64 个完整
任务里它是唯一没有 CSV 的。已单独补跑该脚本恢复一致。测量数据零损失。

**规则**:有作业在跑时,不要原地修改它们正在执行的脚本。要么等跑完,要么在启动
时把编排脚本拷进 sweep 根目录、从副本执行。
