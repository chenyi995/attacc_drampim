## 晚间:fig:motiv 负载工程与三轮模型修正(chenyi9 逐条纠偏)

- **总指令**:上下文再长、轮次再多、让 PIM/GPU 选边两可、重算比例少一些
  且多跑几个比例(EPIC k∈{2,8,32});四个负载重跑,产出四组 bar chart;
  **先算再跑**;总 CPU 预算 **96 核**(6 档×15 Ramulator worker+6 构图);
  **六档全并行**(脚本由串行改并行发射);
- **修正①(块约定)**:共享内容按**自然 256-token KV 块**切分,轮换下
  一块一 channel;naive 的 row conflict 只许由顺序轮换自己撞出来,
  **不得调块数人为构造**(我最初按"k=8 留 8 条 channel 空转"选参,被纠);
- **修正②(naive 页化)**:大段(history/live)也是先切 256-token 页再
  append(vLLM 分页式)——我此前把整段放单 channel,"大段单 channel 的
  13× 失衡"是造出来的假惩罚,`NaiveKVLayout` 重写为页粒度全局轮换
  (单元验证:30k 行段 118 页摊满 16 channel);
- **修正③(分轮引入)**:真正拉开 A3/A6 的机制 = **小复用块正好轮转
  叠到同一 channel(混叠)**;为让它自然发生,共享文档改为**逐轮引入**
  (每轮首拉 ~1/R 的块、后续轮全量重读)——首次使用定 append 位置,
  复用页天然散布,混叠不由生成器挑选;
- **修正④(扫描语义)**:read-mask(读掩)是 Fugue 的 die 侧硬件特性,
  naive 没有——`shadow_reads=False`:重算 token 从自己 append 位置的页
  **单行激活**读取,所在 chunk 的 master run 在缺口处**断开**
  ("act 一段、act 一个 token、再 act 一段");A3/A4 的 gpu-prefill
  读回新增 **DRAM 侧读事件**(散页碎片在 prefill 也收费);确认
  decode 每 token 每层拉取一次全上下文已建模;
- **合理范围上界发现**:单 (请求,层) 连续 KV 段 ≤ 8 MiB = 32,768 行
  (AttAcc K 分区,越界引擎拒绝)——四负载顶到上界的 76–86%;
- 运行工程:py-spy 抓栈定位预热漏拦聚合入口 `get_time_and_energy`
  (双入口收集修复);预热外层×wrapper 内层**嵌套线程池**击穿 96 核
  预算(load 508),预热期间内层强制为 1;

- **A3a 档新增(chenyi9 深夜裁决)**:阶梯拆出两档 naive——
