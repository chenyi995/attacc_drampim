## 2. F02：A3b 按持久写入序 slot 放置（commit `5e3c564`）

**修改前。** `_striped_append_channel_extents` 的 `slice-append` 分支（`src/workload_runner.py` 旧 916–922 行）
按**本次 scan** 的 unit 序号轮转：第 u 个 unit 落 `(base + u % stripe)`。后果有两个：

- 同一个 chunk 在不同 scan 里落到不同通道（只读 seg2、seg3 的 scan 把它们放到 ch0、ch1，
  全读时却在 ch2、ch3），没有任何存储能做到这一点；每次 scan 都完美均衡，存储也做不到。
- A4c 在 2026-09-04 已改成持久表 `_place_master_by_slot("append")`，A3b 没改，
  于是 A3b → A4c 的差不只是 diff 聚合，master 放置也变了，claim 1 的归因不干净。

**修改后。** master 走与 A4c 同一张表 `_place_master_by_slot("append")`（`_chunk_slot_table(mode="append")`，
第 i 个写入的 chunk 落 slot `i % stripe`，之后每个 scan 都查这张表）。
修正没有 diff 区可去，仍留在同一条轮转里：按 `(owner, fingerprint)` 分组，
`tlb.chunk_slot("diff:<owner>:<fp>", stripe, "append")` 在首次出现时追加到表尾，之后持久；
每组的物理连续 run 由 `tlb.scan_runs` 给出，每个 run 一个 row 对齐 extent。
同一 head 一轮里一起产生的修正仍是一段连续 append（chenyi9 2026-09-03 裁决），注释里的算例原样保留。
无分配器（probe / 单测）时保持旧的按 scan 轮转，`_place_master_by_slot` 本来就这样回退。

**简化（推测，未按真实写入流验证）。** 修正的 slot 顺序是"所有 master chunk 之后、按首次被扫描到的顺序"，
不是真实单流里 chunk 与修正交错的写入顺序。选它的原因是 chenyi9 对 A4c 的定义是"master 不动"：
A3b 与 A4c 的 master 必须落同一通道，A3b→A4c 只差 diff 去向。若用 `NaiveKVLayout.finalize`
的 16 通道页轮转（含修正的真实写入序）做 slot，master 会随修正数量错位，与 A4c 不再同表。

**回归测试。** `tests/test_placement.py::test_a3b_chunk_keeps_its_channel_across_scans`：
同一分配器上全读与只读 seg2/seg3 两次 scan，seg2/seg3 都在 ch2/ch3，ch0/ch1 为 0；
`master-diff-local-append`（A4c）对同一读集给出同样的 master 通道。
既有 `test_a3b_cost_is_monotone_in_k`、`test_worked_example_a_b_c_d_e_f` 不变、仍过。

## 3. F04：fresh prefill 按档选边（commit `79fbc76`）

**修改前。** `run_cacheblend_dag` 里 `if not reusable:`（旧 4196 行）无条件把无复用行的层放到 GPU，
不看 `pim_prefill_mode`。A5（`prefill_attn: pim`）从没把一个 fresh 请求的 prefill 放进 bank；
A6 的选边器从没见过 fresh 请求，`pim_prefill_sides` 里没有它们。

**修改后。**

- 把可复用分支里的选边代码原样抽成 `_resolve_prefill_side(...)`：`gpu` / `pim` 照给；
  `dynamic` 用同一套模型给 xPU 侧（回读 + 整段 GPU attention）和 bank 侧
  （最忙通道的 sweep × 次数 + Q/ctx 链路）定价，`t_bank <= t_xpu` 选 PIM，
  每个请求只在第一次遇到的层决定一次，记入 `dynamic_prefill_sides`。定价公式一个字没改。
- fresh 层先调 `_resolve_prefill_side`（resident 集为空）：
  - `gpu` → 新函数 `_append_gpu_prefill_layer`（见 §4），事件名从 `gpu_score/softmax/context`
    改为与复用分支 GPU 侧一致的 `gpu_prefill_*`，并显式 `op.numOp = heads`
    （模板 numOp 为 `num_heads/tp × batch`，batch=1 时相同；未单独做数值等价核对）。
  - `pim` / `dynamic→pim` → 不再短路，落入下面的拆分路径：`old_reads` 为空、`writes` 为全部 fresh 行，
    走 A5 同一条 bank-whole 路径（`dram_store_diff_and_live` → sweep → `die_score_assembly` → `ctx_pim_to_gpu`）。
    不伪造 resident 回读，注释里的原意保留。

**回归测试。** `tests/test_workload.py::test_fresh_prefill_follows_the_rung_prefill_side`：
纯 fresh 请求在 `gpu` 下有 `gpu_prefill_score`、无 bank scan；在 `pim` 下有 bank scan 与
`die_score_assembly`、无 `kv_pim_to_gpu`、GPU 侧行数为 0；`dynamic` 下 `pim_prefill_sides` 含该请求，
事件属于所选的一侧。
`test_cacheblend_emits_trace_ordered_tlb_and_physical_addresses` 里 pipe 与 serial 的对比原来是
`pim` 对 `dynamic`（不是同一个 DAG）：修复后 fresh 的 supervisor 在 `pim` 下进 bank、在 `dynamic` 下选 GPU，
串行反而更快，断言失败；改为两次都 `pim_prefill_mode="pim"`，比较的才是同一个 DAG。

## 4. F01：A1 的 prefill 回到 GPU（commit `8e2c796`）

**修改前。** `physical_no_reuse`（A1）分支先 `side_rows["gpu"] += L`，再调
`_append_physical_no_reuse_prefill_layer`——那是一次 bank 内的连续扫描（`Acc.get_time_and_energy`）。
A1 名义上是 AttAcc 原样（prefill 在 GPU、decode 在 bank），实际 prefill 跑在 PIM、报表记成 GPU。

**修改后。** A1 分支也调 `_resolve_prefill_side`（A1 preset 是 `gpu`）：

- `gpu` → `_append_gpu_prefill_layer`：GPU 算 QKV（fresh 行），K/V 立刻上链路 `kv_gpu_to_pim`；
  若有驻留历史（bindings 里 reused 标记的行）先 `dram_read_resident` + `kv_pim_to_gpu` 回读，
  与复用分支 GPU 侧同一做法；`gpu_prefill_score / softmax / context`，`m = fresh`、`n(k) = fresh + history`；
  后接 `_post_attention_gpu`；最后 `_append_channel_kv_stores(name="dram_store_master")` 按通道落 K/V。
  设备归属从实际分支计入。
- `pim` → 原 `_append_physical_no_reuse_prefill_layer` 不动，供私有布局下的 bank 扫描对照。

**回归测试。** `tests/test_workload.py::test_a1_prefill_runs_on_the_gpu_and_lands_kv_for_pim_decode`
（带 2 行历史）：有 `gpu_prefill_*`、`kv_pim_to_gpu`（2 行）、`dram_store_master`；
无 `pim_kv_scan_score_softmax_pv`、`contiguous_address_plan`、`q_gpu_to_pim`；
decode 仍有 bank scan；`prefill_attention_rows["pim"] == 0`。
原先钉住 bank 扫描几何的 `test_physical_no_reuse_uses_private_contiguous_16_channel_kv`、
`test_history_widens_the_physical_no_reuse_scan` 改为显式 `pim_prefill_mode="pim"`，断言不变。
