# Fugue simulation scope

The native AttAcc model is pinned to source commit `c60005143a6b492d7ef83231723386478b59a506`. The included source lock covers the GPU cost/energy model, model geometry, decode scheduling, PIM trace generator, mapping and DRAM timing implementation. Pinned upstream Ramulator is `b7c70275f04126c647edb989270cc429776955d1`.

The final experiment model is LLAMA-7B, 32 layers, hidden dimension 4096, 32 MHA heads, head dimension 128, FP16, native A100a and five HBM stacks. A100a is AttAcc's modeled A100/HBM3 configuration. The default NVLink 3 one-way bandwidth is 300 GB/s; PCIe 4 and NVLink 4 bound the sensitivity range at 32 and 450 GB/s. No fixed link-startup intercept is added. Eight resident queries share each MQ KV scan; tCK=0.769 ns and the 1–8-query intervals are 6/7/7/7/7/8/8/8 cycles. Query-private movements and tail groups remain charged.

For experiments 1/2, N=C+Q and the historical KV is initially only on PIM. GPU service is `max(GPU_attention + cached_KV_readback, new_KV_write)`. PIM service is `Q_input + scan + standalone_PIM_softmax + max(0,new_KV_write-W) + output_return`. W is the first group's scan-launch-to-first-new-K-MAC window measured from native commands; C=0 gives W=0. Attention is the original rectangular Q×N, with independent QK, softmax and PV GPU operators. It is not FlashAttention and does not receive a causal-triangle discount.

Workload variants are F1 (passive remote cache; GPU prefill/decode), F2 (full private KV materialization; GPU prefill/native PIM decode), F3 (shared old KV and private new/recomputed versions; prefill fixed GPU), and F4 (F3 storage plus minimum complete GPU/MQ prefill service). F2 retains native serial full export; F3 overlaps diff export as in the service model. A separate F2 export-overlap sensitivity prevents attributing this scheduling difference entirely to capacity savings. Scattered recomputation uses W=0 conservatively.

CacheBlend has full first-layer attention, full QKV at the check layer, and 16% old-token recomputation plus the suffix thereafter. EPIC's kvlink-16 selects the first sixteen tokens of each document and the whole query before layer zero. Updated positions replace old KV rather than increasing N. Immutable source chunks are counted once; private updates, decode tokens and simultaneous GPU scratch are counted separately. Under concurrent EPIC readers, native GPU batch shapes and ceil(32B/5) PIM heads per stack are actually profiled. There is no request/batch latency extrapolation.

TTFT includes the ordered QKV→attention service→projection/FFN/norm path over 32 layers. TBT is the mean remaining native decode step; E2E is TTFT plus those steps. Fixed output caps are ten tokens for CacheBlend and sixteen for EPIC; they are not measured answer lengths. Batch latency is not divided by batch size. Energy is the native dynamic-energy accounting, with pJ converted to J; overlap changes time, not transaction energy. The original combined PIM score energy convention and link-only transfer energy are retained. Static board power, extra endpoint DMA energy, RoPE, top-k runtime, LM head and host scheduling are not added where the original model does not supply them.

This is a deterministic hardware-cost replay, not a numerical vLLM/EPIC accuracy run. Fixed tokenized inputs avoid requiring tokenizer or weight downloads. Shared-object accounting does not implement a physical shared-address allocator, placement change, cross-request scan coalescing, or a numeric RoPE KV-sharing kernel. See each [experiment README](../Fugue-paper/README.md) for complete formulas, limits and unfavorable results.
