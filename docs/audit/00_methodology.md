# 块 00:审计方法学——公平性准则、完整性准则、核查程序

目标读者:用户与任何要**质疑**本项目数字的人(审稿人、接手人)。
本页定义本目录审计所遵守的专业标准:每条准则都配**可执行的核查方法**,
使读者不必信任助手的叙述,能独立抓出不公平的对比和编造/错标的数字。
逐实验的公平性审查结果在块 07,核查的执行记录在块 08。

## 1. 公平性准则(P 系列):对比是否同秤

| 准则 | 内容 | 核查方法 |
|---|---|---|
| **P1 基线不许削弱** | 与 AttAcc/GPU 对比时,基线须为其最强合理形态(GPU 用最优注意力内核模型;AttAcc 用其原生频率与命令流) | 查基线配置旗标;A1/C1 有逐位复现测试锚 |
| **P2 同一负载同一 padding** | 对比双方吃同一 workload JSON、同一矩形 padding、同一 batch 口径 | 对比报告里的 `lin/lout/batch` 字段 |
| **P3 同一物理秤** | 时间同一 tCK 换算;能耗同一 `ENERGY_TABLE`;面积同一工艺+corner+综合流程,跨秤只报倍数/占比 | 查换算链每步出处(块 06 §5) |
| **P4 同频对比优先** | 频率不同的两点对比必须显式声明,且尽量提供同频行 | 查结果表是否含同频行 |
| **P5 对比双方同一代码路径** | 同一事件 DAG/同一解析模型,不许一方走精细路径另一方走粗路径(除非明确声明为跨路径校验) | 查 driver 脚本的旗标差异 |
| **P6 软输入显式声明** | 任何非本仓实测的输入(文献读图值、外部 benchmark、假设参数)须标注并说明影响方向 | grep 模型文件头注与常数定义 |

## 2. 完整性准则(I 系列):防"乱搞"

| 准则 | 内容 | 核查方法 |
|---|---|---|
| **I1 数字可溯源** | 结论里的每个数字有出处(文件/命令/论文节),且属于实测/推导/悬置三类之一 | 抽查:按出处重算/重跑 |
| **I2 可独立复现** | 关键数字给出复现命令,不依赖助手在场 | 跑块 08 §6 的命令集比对 |
| **I3 代码引用可验证** | `file:line` 引用以**符号名**为准(grep 可到),行号会随改动漂移,以块 08 的核查日期为准 | `grep -n "<符号名>" <file>` |
| **I4 改动面对账** | 每个 commit/工作区改动的文件清单须与声明的改动范围一致,无未声明的顺手改动 | `git log --stat` / `git status` 对照各块"归属"节 |
| **I5 行为不回退** | 新功能在关闭态(默认值/H=0)必须与改动前逐位一致,有测试或等价论证锁住 | 跑全套单测;查等价论证(如块 05 §3 条件等价) |
| **I6 双通道交叉核对** | 关键数字至少两条独立途径可得(如:测试断言 vs 结果 json vs 现场运行) | 块 08 §3 记录 |
| **I7 反事实检查** | 声称"X 不变/不涨"的结论要给出对照运行的证据,不许只讲道理 | 如块 05 §4 的链路字节对照 |

## 3. 引用规范

- 代码引用格式:`文件路径:行号`(行号为**辅助**,符号名为**准**);
  行号有效期截至块 08 头部标注的核查日期与工作区状态。
- 数字引用格式:值 + 出处 + 类别(实测/推导/悬置)。
- 文献引用:论文名+节号;论文 PDF 在 `KVPIM-1Fugue-ASPLOS2027/ref/`。

1. `src/ramulator_wrapper.py` 的 `tCK=0.769 ns` 秒换算口径(AttAcc 沿袭,
   `HANDOFF.md` §3.4);

   mq,`HANDOFF.md` §3.5);

5. 论文正文数字纪律:须用户手动复现才能进正文,否则 `\TBDnum`
   (论文仓库 CLAUDE.md);
6. 面积绝对值(µm²/mm²)不进论文正文,只报倍数/占比(`HANDOFF.md` §3.8)。

## 5. 审计的局限(如实声明)

- 本目录由助手撰写,存在**自我审计**的固有利益冲突;缓解手段是:
  每条结论可独立复现(I2)、核查命令公开(块 08 §6)、错位历史如实
  记录(块 06 §7、根 CLAUDE.md 历史教训)。最终把关是用户按块 08
  命令集抽查。
- 未做:结果 json 的密码学校验(哈希清单)、CI 自动跑核查命令。
  是否需要,待用户裁决。
