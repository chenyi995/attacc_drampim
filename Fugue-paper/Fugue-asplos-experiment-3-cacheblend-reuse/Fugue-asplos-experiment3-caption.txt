Native AttAcc cost replay of the two smallest complete CacheBlend demo inputs. F1 uses remote HBM only as a software cache and executes attention on GPU; F2 materializes a private full KV view for native PIM decode; F3 stores only new/recomputed KV versions while fixing prefill on GPU; F4 selects prefill per layer using complete GPU/MQ PIM service costs. Latency and dynamic-energy bars average the two requests; capacity is the maximum simultaneous KV payload, including the shared cache but excluding common GPU weights. Each request has ten output tokens. The main F2 preserves native serial prefill export; the export-overlap sensitivity is reported separately. These are modeled timings and native dynamic energies, not measured LLM answer quality or board energy.
