## 8. 链路带宽与容量分层

chenyi9 提议按 context 大小分级，快层通过 NVLink，超出后通过 PCIe；此处将“KV link”按 NVLink 理解。它可作为额外实验假设，但降带宽不能保证 A5/A6 拉开。

设一次 prefill 的 GPU KV 回读为 D_G，PIM context 返回为 D_P，g 为 GQA group。当前代码的字节关系是 `D_G = 2R × KV宽度 × word_bytes`、`D_P = m × query宽度 × word_bytes`，因此 `D_G/D_P = 2R/(g m)`。m/R 都取实际请求，不能仅用总 context 长度判断。

当链路成为瓶颈且两种传输都使用同一有效带宽 B，局部价格差 `P−G = 固定计算项 + (D_P−D_G)/B`，A6 相对固定 PIM 的选择优势仍是 `max(P−G,0)`。

- 仅降低 GPU 回读带宽：G 增大，A6 更多选择 PIM，A5/A6 的局部差距缩小或不变。
- 大量复用 KV、少量 query：通常 D_G>D_P，统一降低链路带宽也更伤 GPU 路径；更适合展示 A4e→A5 的驻留收益。
- 大量 fresh query、R 接近零：GPU 没有驻留 KV 回读，PIM 的 context 返回变慢，A5/A6 差距可能扩大。
- 混合这两类请求：可以展示逐请求选边价值；E2E 还受共同写回、decode 传输和排队影响，不能从局部公式预先保证涨幅。

对 GQA={gqa}，回读量大于返回量的条件为 `R>{gqa//2}m`。带宽仍高于远端 HBM 可供数据的速度时，继续降带宽也可能暂时不改变服务时间。

容量阈值建议按快层**净 KV 字节容量**推导，而不是为拉开结果挑 context 阈值。全模型原始 KV：`bytes/token = 2 × layers × KV_heads × head_dim × word_bytes`。仓库 LLAMA3-8B、fp16、TP=1 得到每 token {bytes_per_token:,} B（{bytes_per_token//1024} KiB）：

{table}

这些是明确假设的快层 KV 配额，不是现有硬件的可用容量实测。若选净 KV 容量 16 GiB，可以先以 131,072 个唯一 token 作为不含额外开销的容量上限；真实阈值须计入各档实际 master/diff/padding，并扣除保留空间。多个 request 共用该层时按全局唯一驻留 KV 计数，共享 chunk 只存一份，不能让每个请求都独占这个阈值。

真正溢出应按地址分层：未溢出的实际读取走 NVLink，溢出部分走 PCIe；不是 context 一越线，全部 KV 都突然变 PCIe。串行读取时两部分时间相加；若独立链路/设备能并行，按真实资源依赖取完成时间。PCIe 后端若仍能做 PIM，说明其 PIM 能力和容量；若是普通主存，则不能让 A5 免费在该处沿用 HBM-PIM 扫描价格，需说明搬运路径。

这组层级是所有档共用的硬件与放置规则，A5/A6 保持同一存储布局，仅选边不同。现有 AttAcc 能量系数保持原口径，不额外发明分层/TLB 能耗。[容量推导证据](../../audit/2026-09-05/archive/link_tier/capacity_evidence.json)；当前实现与上游边界见 [链路审计](../../audit/2026-09-05/LINK_TIER_ASSUMPTIONS.md)。
