**A4 在 baseline 上几乎没有正收益**:最坏的 LLAMA3-8B 倒亏 30%,中间三个模型基本
打平。机制与 0903 轮一致 —— A4 让出 ch15 给 diff 池后 master 池只剩 15 条,
`stripe_m` 从 `16 // heads_per_hbm` 掉到 `15 // heads_per_hbm`,LLAMA3-8B 正好跨过
整除边界、每 head 的 stripe 腰斩。**A4b 用全局 co-read table 把它修回来**,
这才是有效的那一步。

**A6 只在 LLAMA-7B 与 LLAMA3-8B 上赢过 A5**;其余四个模型 A6 与 A5 逐位相同。
不是退化,是动态选边器与 A5 那份固定的 "prefill 一律上 PIM" 菜单**结论一致**。
在那两个 `--num-hbm 1` 的模型上它把 prefill 全撤回 GPU 并且赢了 —— 分界线正是
master stripe 塌成 1 条 channel(`heads_per_hbm` 32 与 8)。

`09b50fb` 预测 A3b 会**变慢**(k=8 时最忙 channel +12.5%),实测是**变快 4–7%**。
方向相反。已排除:TLB 计划时间(差 3 个数量级)、放置/extent 模型(本形状下新旧
最忙 channel 完全相同)、`masked_rows`(不进 `ramulator_wrapper`)、GPU 时间
(逐位相同)、事件数与 ablation 配置(完全一致)。

tiny 负载上的 A/B 只差 0.035%,但那个负载 prefill 主导、**不能代表 decode 主导的
baseline**,不足以下结论。**决定性实验(用修复前代码同机重跑 GPT-13B A3b)已提交但
随停机取消。**

> **在查清之前,不要把本轮 A3b 与 0903 轮 A3b 的差异归因于 `09b50fb`。**
> 也不要把两轮的 A3b 混在一张图里。

## 口径

与 0903 轮**只差 `09b50fb` 一处**;column-packed extent 模型、`heads_per_hbm`
按 per-GPU stack、`num_hbm` 能量修复、C=16 / sys=256 的 workload 两轮相同。
本轮 baseline 的 A1/A2/A4/A4b/A5/A6 与 points 的部分 A5/A6 是从 0903 轮
**硬链接复用**的(那些档不受 `09b50fb` 影响,逐位有效)。
